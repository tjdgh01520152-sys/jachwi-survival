# 자취생 생존기

남은 식비로 며칠 동안 몇 끼를 해결할 수 있을지 알려주는 예산 기반 식사 생존 플래너입니다.
안암/고려대 근처를 중심으로, Kakao Local API에서 가져온 실제 식당 + 내부 요리 데이터 + 편의점을
섞어서 3가지 생존 플랜을 추천합니다.

## 왜 만들었나

자취를 하다 보면 "이번 달 식비로 며칠을 버틸 수 있을까"라는 질문에 답을 주는 서비스가 없었습니다.
맛집 추천 앱은 많지만, "예산 제약이 있는 상태에서 여러 끼니를 어떻게 배분해야 굶지 않고 버틸 수 있는지"를
계산해주는 곳은 없어서 직접 만들었습니다.

## 실행 방법

```bash
git clone https://github.com/tjdgh01520152-sys/jachwi-survival.git
cd jachwi-survival
npm install
cp .env.example .env.local   # 이미 생성되어 있다면 생략
# .env.local 에 카카오 REST API 키를 채워주세요
npm run dev
```

`http://localhost:3000` 접속 후 "안암역 / 40,000원 / 8끼" 처럼 입력하고
"생존 플랜 보기"를 누르면 됩니다.

### Kakao REST API 키 발급

1. https://developers.kakao.com 에서 애플리케이션 생성
2. **제품 설정 > 카카오맵**을 켜야 Local API(키워드/카테고리 검색)가 동작합니다 (기본적으로 꺼져있음)
3. 내 애플리케이션 > 앱 키 > REST API 키 복사
4. `.env.local`의 `KAKAO_REST_API_KEY`에 붙여넣기

키가 없거나 카카오맵 제품이 꺼져있어도 화면은 깨지지 않습니다. 안암역 주변 예시 데이터로
자동 대체되고, 화면 상단에 이유가 담긴 안내 배너가 표시됩니다.

## 데모 시나리오

1. 기본값 그대로 "안암역 / 40,000원 / 8끼" 상태에서 **생존 플랜 보기** 클릭
   → Kakao API로 안암역 주변 실제 식당/편의점을 가져와 생존 등급(예: "생계형 편의점 계급 · 삼김 라면
   연합군", 한 끼 평균 5,000원), 예산 사용률, 최대 절약 / 균형 / 가까운 곳 위주 3개 플랜이 뜬다
2. 균형 플랜의 끼니 카드 하나에서 **"너무 멀어요"** 클릭
   → 그 자리만 더 가까운 실제 식당으로 교체되고, 예상 지출·한 끼 평균·생존 등급이 함께 재계산된다
3. 마음에 안 드는 식당은 **"이곳 제외하기"**
   → 이후 모든 추천(전체 다시 추천 포함)에서 그 식당이 계속 빠진다 (localStorage에 저장)
4. 옵션에서 **"나눠먹기 가능"**을 켜고 다시 추천
   → 엽기떡볶이 같은 나눠먹기 메뉴가 일부 끼니에 섞여 나오고, "총 14,000원 · 2명 기준 내 부담
   7,000원" 형태로 표시된다
5. 예산을 극단적으로 낮게 입력 (예: 8끼에 10,000원) 후 다시 추천
   → 일반 3플랜 대신 **"텅장 경보"** 최저 생존 플랜 화면으로 전환되고, "9끼 중 4끼만 해결 가능해요"
   식으로 몇 끼가 비는지 보여주며 "예산 5,000원 늘리기" / "나눠먹기 켜기" 버튼으로 바로 개선해볼 수 있다
6. 예산을 다시 넉넉하게(예: 8끼에 100,000원) 바꿔서 재추천
   → 균형/가까운 곳 플랜이 세트 메뉴·든든한 외식 위주로 바뀌며 예산의 85~95% 수준을 자연스럽게 사용한다
   (최대 절약 플랜은 예산과 무관하게 항상 저렴하게 유지되는 걸 대조해서 보여줄 수 있음)
7. **"전체 다시 추천"**을 여러 번 클릭
   → 같은 조건이라도 매번 다른 조합의 플랜이 나온다

## 기술 스택

- Next.js 14 (App Router) + React + TypeScript
- Tailwind CSS
- Kakao Local API (키워드/카테고리 검색) — 서버 API route(`/api/restaurants`)에서만 호출, 키는 프론트엔드에 노출되지 않음
- 룰 기반 추천 알고리즘 (서버 호출 없이 클라이언트에서 재계산 — 카드 피드백/제외/다시 추천이 즉시 반영됨)
- localStorage 기반 개인화 (로그인/DB 없음)

## 핵심 흐름

1. 위치 → Kakao 키워드/주소 검색으로 좌표 변환
2. 좌표 기준 반경 1,200m 내 음식점(FD6)·편의점(CS2) 거리순 조회, 카페/디저트류는 후보에서 제외
3. 상호명이 등록된 프랜차이즈(맘스터치, 한솥도시락, 동대문엽기떡볶이 등)와 매칭되면 단품/세트/
   나눠먹기 기준가를, 그 외에는 카테고리·상호명 키워드로 가격대를 추정
4. 내부 요리 데이터(카레, 김치볶음밥 등)를 후보에 합류
5. "모든 끼니를 최저가로 채워도 예산이 부족한지" 먼저 판정 → 부족하면 텅장 경보 + 최저 생존 플랜 화면
6. 아니면 예산 적합도·취향(좋아하는 것 가점/피하고 싶은 것 감점)·거리·든든함·다양성 점수로 후보를
   채점 — 한 끼 평균 예산 구간(3천/6천/1.2만원)에 따라 요리·편의점·외식·세트 비중이 구조적으로 조정됨
7. 최대 절약 / 균형 / 가까운 곳 위주, 3가지 플랜 생성 후 후처리: 연속 메뉴·식당 방지, 예산 사용률
   85~95%로 업그레이드/다운그레이드
8. 한 끼 평균 예산에 따라 생존 등급(냉장고 파먹기 ~ 귀족 자취생 계급 + 세부 칭호) 표시, 실제 지출
   기준이라 카드 하나를 바꾸면 등급도 같이 바뀜
9. 카드 피드백("너무 멀어요", "비싸요", "안 끌려요", "이곳 제외하기")이 localStorage 개인화 상태에
   반영되고, 다음 추천부터 자동으로 가중치에 반영됨
