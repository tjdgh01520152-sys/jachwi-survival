# 자취생 생존기

남은 식비로 며칠 동안 몇 끼를 해결할 수 있을지 알려주는 예산 기반 식사 생존 플래너입니다.
안암/고려대 근처를 중심으로, Kakao Local API에서 가져온 실제 식당 + 내부 요리 데이터 + 편의점을
섞어서 3가지 생존 플랜을 추천하고, 결과를 지도로도 보여줍니다.

## 왜 만들었나

자취를 하다 보면 "이번 달 식비로 며칠을 버틸 수 있을까"라는 질문에 답을 주는 서비스가 없었습니다.
맛집 추천 앱은 많지만, "예산 제약이 있는 상태에서 여러 끼니를 어떻게 배분해야 굶지 않고 버틸 수 있는지"를
계산해주는 곳은 없어서 직접 만들었습니다.

## 주요 기능

- **실시간 위치 기반 추천** — Kakao Local API로 입력한 위치 주변 실제 식당·편의점 데이터를 가져와
  추천합니다 (더미 데이터 아님).
- **예산 기반 3가지 생존 플랜** — 최대 절약 / 균형 / 가까운 곳 위주 플랜을 동시에 생성하고, 예산이
  커질수록 세트·든든한 메뉴 비중이 자연스럽게 늘어나도록 설계했습니다.
- **생존 등급 시스템** — 한 끼 평균 예산에 따라 "냉장고 파먹기 계급"부터 "귀족 자취생 계급"까지
  재미있는 등급과 칭호를 부여합니다. 카드 하나를 바꾸면 실제 지출 기준으로 등급도 즉시 재계산됩니다.
- **안암 생존 지도** — 추천된 끼니를 카카오맵 위에 번호 핀으로 표시하고, 끼니 카드를 누르면 해당
  지도 핀이 강조됩니다. 직접요리처럼 실제 위치가 없는 끼니는 자연스럽게 지도에서 빠집니다.
- **실시간 카드 피드백** — "너무 멀어요", "비싸요", "안 끌려요", "이곳 제외하기"를 누르면 그 자리만
  즉시 재계산되고, 제외한 곳은 이후 모든 추천에서 계속 빠집니다 (localStorage 기반, 로그인 불필요).
- **나눠먹기 옵션** — 치킨·찜닭·양꼬치 등 원래 나눠 먹는 메뉴는 프랜차이즈 여부와 무관하게 나눠먹기
  후보로 반영되고, 총액과 1인당 부담금을 함께 보여줍니다.
- **취향 필터** — 좋아하는 음식은 가점, 피하고 싶은 음식은 후보에서 아예 제외됩니다 (감점이 아니라
  완전 배제).
- **예산 초부족 대응 ("텅장 경보")** — 최저가로 채워도 예산이 부족하면 억지로 끼워 맞추지 않고, 몇
  끼가 해결 가능한지 보여주며 "예산 5,000원 늘리기" 같은 실질적 대안을 제시합니다.
- **직접요리 반영** — 내부 요리 데이터 10종을 후보에 포함시켜 장보기 총액과 몇 끼가 해결되는지 함께
  보여줍니다.

## 실행 방법

```bash
git clone https://github.com/tjdgh01520152-sys/jachwi-survival.git
cd jachwi-survival
npm install
cp .env.example .env.local   # 이미 생성되어 있다면 생략
# .env.local 에 카카오 REST API 키(+선택: 지도용 JavaScript 키)를 채워주세요
npm run dev
```

`http://localhost:3000` 접속 후 "안암역 / 40,000원 / 8끼" 처럼 입력하고
"생존 루트 뽑기"를 누르면 됩니다.

### Kakao REST API 키 발급 (필수 — 식당/편의점 데이터)

1. https://developers.kakao.com 에서 애플리케이션 생성
2. **제품 설정 > 카카오맵**을 켜야 Local API(키워드/카테고리 검색)가 동작합니다 (기본적으로 꺼져있음)
3. 내 애플리케이션 > 앱 키 > **REST API 키** 복사
4. `.env.local`의 `KAKAO_REST_API_KEY`에 붙여넣기 (서버 전용 — 프론트엔드에는 절대 노출되지 않음)

키가 없거나 카카오맵 제품이 꺼져있어도 화면은 깨지지 않습니다. 안암역 주변 예시 데이터로
자동 대체되고, 화면 상단에 이유가 담긴 안내 배너가 표시됩니다.

### Kakao Maps JavaScript 키 발급 (선택 — 결과 지도)

결과 화면의 "안암 생존 지도"는 REST API 키와는 **별개의 키**를 씁니다.

1. 같은 애플리케이션의 내 애플리케이션 > 앱 키 > **JavaScript 키** 복사
2. **플랫폼 설정 > Web**에 사용할 도메인 등록 (로컬은 `http://localhost:3000`, 배포하면 실제 도메인도 추가)
3. `.env.local`의 `NEXT_PUBLIC_KAKAO_MAP_KEY`에 붙여넣기

이 키는 브라우저에서 지도를 직접 그리기 때문에 페이지 소스에 노출되는 게 정상입니다(카카오맵 SDK
설계상 원래 그렇습니다). 보안은 비밀로 숨기는 게 아니라 위 2번의 도메인 화이트리스트로 겁니다.
키가 없어도 화면은 깨지지 않고, 같은 정보(내 위치 + 번호 매겨진 매장 목록 + 거리)를 보여주는
목록형 대체 화면으로 자동 전환됩니다.

## 데모 시나리오

1. 기본값 그대로 "안암역 / 40,000원 / 8끼" 상태에서 **생존 루트 뽑기** 클릭
   → 안암/안암역 입력은 실시간 Kakao 검색 대신, 직접 조사해 큐레이션한 안암 근처 45곳 데이터
   (평점·가격대 포함)로 추천이 만들어진다. 생존 등급(예: "생계형 편의점 계급 · 삼김 라면 무한 반복",
   한 끼 평균 5,000원), 예산 사용률, 최대 절약 / 균형 / 가까운 곳 위주 3개 플랜, 그리고 결과 요약
   바로 아래 "안암 생존 지도"에 내 위치 + 끼니별 번호 핀이 함께 뜬다
2. 균형 플랜의 끼니 카드 하나에서 **"너무 멀어요"** 클릭
   → 그 자리만 더 가까운 실제 식당으로 교체되고, 예상 지출·한 끼 평균·생존 등급·지도 핀이 함께
   재계산된다 (직접요리로 바뀌면 그 자리 핀은 지도에서 자연스럽게 빠진다)
3. 마음에 안 드는 식당은 **"이곳 제외하기"**
   → 이후 모든 추천(전체 다시 추천 포함)과 지도에서 그 식당이 계속 빠진다 (localStorage에 저장)
4. 옵션에서 **"나눠먹기 가능"**을 켜고 다시 추천
   → 프랜차이즈뿐 아니라 근처 치킨·찜닭·양꼬치·족발보쌈·삼겹살집도 나눠먹기 후보가 되어, 일부
   끼니가 "총 20,000원 · 2명 기준 내 부담 10,000원" 형태로 표시된다
5. 예산을 극단적으로 낮게 입력 (예: 8끼에 10,000원) 후 다시 추천
   → 일반 3플랜 대신 **"텅장 경보"** 최저 생존 플랜 화면으로 전환되고, "9끼 중 4끼만 해결 가능해요"
   식으로 몇 끼가 비는지 보여주며 "예산 5,000원 늘리기" / "나눠먹기 켜기" 버튼으로 바로 개선해볼 수 있다
6. 예산을 다시 넉넉하게(예: 8끼에 100,000원) 바꿔서 재추천
   → 균형/가까운 곳 플랜이 세트 메뉴·든든한 외식 위주로 바뀌며 예산의 85~95% 수준을 자연스럽게 사용한다
   (최대 절약 플랜은 예산과 무관하게 항상 저렴하게 유지되는 걸 대조해서 보여줄 수 있음)
7. **"전체 다시 추천"**을 여러 번 클릭
   → 같은 조건이라도 매번 다른 조합의 플랜이 나온다 (지도 핀도 함께 다시 그려짐)

## 기술 스택

- Next.js 14 (App Router) + React + TypeScript
- Tailwind CSS — "자취생 생존기" 게임풍 리디자인(두꺼운 보더 + 하드 섀도 카드, Black Han Sans /
  Gothic A1 폰트)
- Kakao Local API (키워드/카테고리 검색) — 서버 API route(`/api/restaurants`)에서만 호출, REST 키는
  프론트엔드에 노출되지 않음
- Kakao Maps JavaScript SDK — 결과 지도 전용. REST 키와 별개의 공개 키(`NEXT_PUBLIC_KAKAO_MAP_KEY`)를
  쓰고, 도메인 화이트리스트로 보호. 키가 없으면 목록형 대체 화면으로 자동 전환
- 룰 기반 추천 알고리즘 (서버 호출 없이 클라이언트에서 재계산 — 카드 피드백/제외/다시 추천이 즉시 반영됨)
- localStorage 기반 개인화 (로그인/DB 없음)

## 핵심 흐름

1. 위치 → Kakao 키워드/주소 검색으로 좌표 변환. 단, 위치가 "안암"을 포함하면(예: 안암역, 안암) 실시간
   검색 대신 직접 조사해 큐레이션한 안암 근처 45곳(평점·가격대·나눠먹기 여부 포함) 데이터를 쓴다
2. 좌표 기준 반경 1,200m 내 음식점(FD6)·편의점(CS2) 거리순 조회, 카페/디저트/베이커리/술집류는
   키워드로 후보 풀 생성 단계에서 아예 제외(점수 감점이 아니라 생성 자체를 안 함). 단 "토스트"(이삭토스트
   등 한 끼 대용)·"피자"/"치킨"/"마라탕"/"찜닭"(나눠먹기 메뉴)·분식/김밥/국수/도시락류는 예외로 유지
3. 상호명이 등록된 프랜차이즈(맘스터치, 한솥도시락, 동대문엽기떡볶이 등)와 매칭되면 단품/세트/
   나눠먹기 기준가를, 그 외에는 카테고리·상호명 키워드로 가격대를 추정
4. 치킨·찜닭·양꼬치·족발보쌈·삼겹살처럼 원래 나눠 먹는 메뉴는 프랜차이즈가 아니어도 나눠먹기
   후보로 함께 생성 ("나눠먹기 가능" 옵션을 켰을 때만 적극 추천, 전체 끼니의 10~20%까지만 등장)
5. 내부 요리 데이터 10종(카레, 김치찌개 등)을 후보에 합류 — "장보기 예상 O원 · N끼 해결"로
   표시되고, 직접요리끼리는 연속으로 나와도 됨(카레→카레→편의점→카레 같은 배치가 자연스러움).
   외식/편의점은 여전히 같은 메뉴·식당이 연달아 나오지 않게 관리
6. 후보마다 place_name/카테고리/프랜차이즈 여부 기반 데모용 내부 점수("생존 적합도")를 계산해 동점
   후보를 가르는 약한 보조 기준으로만 반영 — 카카오 평점이 아니고 화면에도 노출하지 않는다
7. "모든 끼니를 최저가로 채워도 예산이 부족한지" 먼저 판정 → 부족하면 텅장 경보 + 최저 생존 플랜 화면
8. 아니면 예산 적합도·취향(좋아하는 것 가점)·거리·든든함·다양성 점수로 후보를 채점 — 피하고 싶은
   것으로 선택한 음식은 채점 전에 후보 풀에서 아예 제외됨. 한 끼 평균 예산 구간(3천/6천/1.2만원)에
   따라 요리·편의점·외식·세트 비중이 구조적으로 조정됨
9. 최대 절약 / 균형 / 가까운 곳 위주, 3가지 플랜 생성 후 후처리: 연속 메뉴·식당 방지, 예산 사용률
   85~95%로 업그레이드/다운그레이드 (단, 나눠먹기로 확보한 끼니는 이 후처리에서 건드리지 않음)
10. 한 끼 평균 예산에 따라 생존 등급(냉장고 파먹기 ~ 귀족 자취생 계급 + 세부 칭호) 표시, 실제 지출
    기준이라 카드 하나를 바꾸면 등급도 같이 바뀜
11. 좌표가 있는 끼니(외식/편의점)만 결과 지도에 번호 핀으로 표시하고, 직접요리는 물리적 위치가 없어
    지도에서 자연스럽게 빠진다. 카드 피드백/제외/다시 추천으로 끼니 구성이 바뀌면 핀도 같이 갱신됨
12. 카드 피드백("너무 멀어요", "비싸요", "안 끌려요", "이곳 제외하기")이 localStorage 개인화 상태에
    반영되고, 다음 추천부터 자동으로 가중치에 반영됨
